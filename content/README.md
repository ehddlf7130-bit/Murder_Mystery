# 시나리오 집필 가이드

이 폴더는 **시나리오 원고**를 쓰는 곳이다. 여기서 쓴 내용을 `src/data/<id>/*.ts`로
옮기면 앱에 반영된다.

## 왜 Markdown으로 따로 쓰나

앱의 데이터는 ID로 서로를 참조한다 — 단서의 선행조건은 다른 단서의 ID 배열이고,
단서의 위치는 구역/인물 ID를 가리킨다. 집필하면서 ID까지 직접 관리하면
오타 하나가 **"단서가 영원히 열리지 않는다"**로 이어진다.

그래서 원고에서는 **모든 것을 이름으로만 참조**한다. ID 부여는 변환할 때 처리한다.

## 쓰는 법

1. `cruise.md`를 연다 (새 시나리오라면 복사해서 새 파일로).
2. 아래 양식대로 내용을 채운다.
3. **저장한다.** 편집기에 떠 있기만 하면 대조에 잡히지 않는다.
4. `npm run check:content`로 코드와 어긋난 곳을 확인한다.
5. 변환을 요청한다 → `src/data/`에 반영되고 `npm test`로 검증된다.

## 원고와 코드, 어느 쪽이 정본인가

같은 내용을 원고와 `src/data/<id>/*.ts`가 이중으로 들고 있어 양쪽으로 어긋난다.
필드마다 **누가 이기는지**가 정해져 있다.

| 범위 | 정본 | 이유 |
|---|---|---|
| 캐릭터의 `#### 배경` 본문 | **원고** | 서사는 원고에서 쓴다 |
| 그 외 전부 — 기본 정보, 층·구역, 캐릭터의 나머지 필드, 단서 전체와 그 순서 | **코드** | 게이팅·구조는 코드에서 정해지고 테스트가 검증한다 |

```
npm run check:content            # 전체
npm run check:content -- cruise  # 하나만
```

출력이 방향을 알려준다.

```
📝 원고 → 코드   원고가 정본 → 코드를 고친다
💻 코드 → 원고   코드가 정본 → 원고를 고친다
```

차이가 있으면 종료 코드 1로 끝난다. **`npm test`에는 포함되지 않는다** — 집필 중에
잠깐 어긋나는 것은 정상이라 테스트를 깨뜨리면 안 되기 때문이다.

## 양식

파일은 `## 기본 정보` → `## 구역` → `## 캐릭터` → `## 단서` 순서로 쓴다.
**제목 기호(`##`, `###`, `####`)와 `- 필드:` 형태를 그대로 지켜야** 변환이 안전하다.

### 빈 골격

````markdown
# 시나리오: <제목>

## 기본 정보
- 제목: <제목>
- 한 줄 소개: <시나리오 선택 카드에 붙는 홍보 문구>
- 인원: 4~5인
- 플레이타임: 30~60분
- 총 열람 횟수: <숫자>
- 총 힌트 횟수: <숫자>

### 도입부
<심판이 게임 시작 시 낭독하는 글. 여러 줄 가능>

### 공동 목표
- <전원에게 동일하게 주어지는 목표>

### 에필로그
<채점이 끝난 뒤 공개되는 진상. 여러 줄 가능>


## 구역

### <층수>층 · <층 이름>
> <접근 안내 — 생략 가능>

#### <구역 이름> <이모지>
<구역에 들어갔을 때 보여줄 장면 묘사>


## 캐릭터

### <이름> — <직업> <이모지>
- 범인: 예/아니오
- 공개 프로필: <전원에게 공개되는 소개>

#### 배경
<본인 화면에서만 보이는 배경 서사>

#### 개인 목표
- <목표 1>
- <목표 2>

#### 비밀
- <본인만 아는 사실>


## 단서

### <단서 이름>
- 위치: <구역 이름>
- 해제조건: 없음
- 힌트: <다음에 뭘 볼지 유도하는 한 줄>

#### 본문
<열람했을 때 보여줄 내용>
````

### 긴 글의 줄바꿈

도입부·에필로그·배경·본문처럼 여러 줄을 쓰는 곳은 **일반 Markdown 규칙**을 따른다.

- **줄바꿈 하나** = 같은 문단. 변환할 때 공백으로 이어 붙는다.
  → 편집기 폭에 맞춰 자유롭게 줄을 바꿔도 화면에는 한 문단으로 나온다.
- **빈 줄** = 문단 구분. 화면에서도 줄이 나뉜다.

```markdown
#### 본문
이 두 줄은
화면에서 한 문단으로 이어진다.

여기서부터 새 문단.
```

**한글 워드프로세서에서 붙여넣을 때 주의.** 한글·워드에서 복사한 글은 화면 폭에 맞춰
**단어 중간에서** 줄이 끊겨 있다. 그대로 붙이면 위 규칙이 `살` + `았고`를
`살 았고`로 이어 붙인다.

→ 붙여넣은 뒤 **한 문단을 한 줄로 펴서** 넣는다. 문단 사이만 빈 줄로 나눈다.
편집기의 자동 줄바꿈(word wrap)을 켜면 긴 줄도 그대로 읽을 수 있다.
`#### 배경`은 이미 이렇게 정리되어 있으니 그 모양을 따라가면 된다.

## 필드 레퍼런스

### 기본 정보

| 필드 | 필수 | 설명 |
|---|:--:|---|
| 제목 | ✓ | |
| 한 줄 소개 | ✓ | 시나리오 선택 카드의 한 줄 문구 |
| 인원 | ✓ | `4~5인` 처럼 자유 문자열 |
| 플레이타임 | ✓ | `30~60분` |
| 총 열람 횟수 | ✓ | 게임 전체에 허용되는 단서 열람 횟수 |
| 총 힌트 횟수 | ✓ | 게임 전체에 허용되는 **힌트** 열람 횟수. 열람 횟수와 별개 예산 |
| `### 도입부` | ✓ | 심판 낭독용. 여러 줄 |
| `### 공동 목표` | | `-` 목록. **전원에게 동일하게** 주어지는 목표. 개인 목표와 달리 체크할 수 없고, 각자의 캐릭터 시트 '목표' 탭 맨 위에 읽기 전용으로 뜬다. 없으면 섹션을 생략 |
| `### 에필로그` | ✓ | 채점 후 공개되는 진상. 여러 줄 |

### 구역

구역은 **층(데크)으로 묶는다.** 층을 `###`, 구역을 `####`로 쓴다.

```markdown
### 4층 · 브리지 데크
> 승객 출입 금지

#### 선장실 🧭
4층 브리지 옆 선장 전용 공간. ...
```

- `### <층수>층 · <층 이름>` — 층수는 숫자로 시작해야 한다
- `> 접근 안내` — 인용 한 줄. 층 이름 옆에 작게 붙는다. 생략 가능
- `#### <구역 이름> <이모지(선택)>` 다음 줄부터 진입 시 묘사
- 맵 화면은 **높은 층부터 아래로** 쌓아 배의 단면도처럼 보여준다.
  층 안에서의 순서 = 파일에 쓴 순서
- 층수는 서로 겹치면 안 된다 (검사기가 오류로 잡는다)

**층이 필요 없는 시나리오**(단층 저택 등)는 층 구분을 생략하고 구역을 `###`로
바로 쓰면 된다. 그 경우 맵은 지금까지처럼 평평한 그리드로 나온다.

### 캐릭터

`### <이름> — <직업> <이모지(선택)>` (구분자는 em dash `—`)

| 필드 | 필수 | 설명 |
|---|:--:|---|
| 범인 | ✓ | `예` / `아니오`. **정확히 한 명만 `예`** |
| 공개 프로필 | ✓ | 전원에게 공개. 다른 플레이어도 본다 |
| `#### 배경` | ✓ | 본인 개인 화면에서만 보이는 서사 |
| `#### 개인 목표` | ✓ | `-` 목록. 본인이 체크할 수 있다 |
| `#### 비밀` | | `-` 목록. 없으면 섹션을 생략 |

### 단서

`### <단서 이름>`

| 필드 | 필수 | 값 | 설명 |
|---|:--:|---|---|
| 위치 | ✓ | `<구역 이름>` 또는 `소지품 / <캐릭터 이름>` | 구역·캐릭터 섹션에 쓴 이름과 정확히 일치해야 한다 |
| 해제조건 | ✓ | `없음` 또는 `단서 이름, 단서 이름` | **다른 단서의 이름**으로 참조 |
| `#### 본문` | ✓ | 여러 줄 | 열람했을 때 보여줄 내용 |
| 힌트 | | 한 줄 | 다음에 뭘 볼지 유도. **힌트 예산을 따로 소모해야** 보인다 |
| 힌트 비용 | | 숫자 | 미지정 시 1회. `0`이면 무료로 열린다 |
| 잠김이름 | | 문자열 | 쓰면 **특수 단서 탭**에 노출되고, 잠긴 동안 이름 대신 표시된다 |
| 잠김힌트 | | 한 줄 | 잠긴 카드에 뜨는 뉘앙스 |
| 비용 | | 숫자 | 기본 규칙(아래)을 덮어쓴다 |
| 숨김 | | `예` | 잠긴 동안 **구역 목록에서 아예 감춘다**. 특수 단서 탭에는 계속 보인다 |

## 게이팅 설계 규칙

해제 조건을 설계할 때 코드가 강제하는 규칙이다.

**1. 비용은 자동으로 정해진다.**
`해제조건: 없음` → **1회 차감**. 해제조건이 하나라도 있으면 → **무료(0회)**.
하위 단서를 모은 것 자체가 보상이기 때문이다.
즉 열람 예산은 **하위 단서 수집에만** 쓰이고, 상위 단서는 그 결과로 얻는다.
"어렵게 얻는 단서니까 비싸게"는 반대로 동작하므로, 예외가 필요하면 `비용:`을 직접 쓴다.

**2. 해제조건은 "열람 완료" 기준이다.**
잠금이 풀린 것만으로는 다음 단계를 열지 못한다. 실제로 열어 봐야 한다.

**3. 특수 단서를 다른 단서의 해제조건으로 넣으면 연쇄 게이팅이 된다.**
예: `부검 정밀 결과` → `정하람의 소지품`.

**4. 진입 단서가 최소 1개 있어야 한다.**
`해제조건: 없음`인 단서가 하나도 없으면 게임을 시작할 수 없다.

**5. 순환 금지.**
A가 B를, B가 A를 요구하면 둘 다 영원히 안 열린다. 검사기가 오류로 잡는다.

**6. 총 열람 횟수 < 유료 단서 총합.**
전부 열 수 있으면 선택의 긴장이 사라진다. 이 경우 검사기가 밸런스 경고를 낸다.
목표로 삼을 만한 기준: **특수 단서를 전부 해제하는 최소 경로 + 2~3회** 정도.
`총 힌트 횟수`도 같은 기준으로 검사한다 — 유료 힌트를 전부 살 수 있으면 경고.

**7. 힌트는 열람 예산과 완전히 별개인 예산을 쓴다.**
단서 본문을 연 **뒤에야** 그 단서의 힌트를 살 수 있고, `총 힌트 횟수`에서 차감된다.
한 번 산 힌트는 이후 무료다. 구매 전에는 화면에 `💡 힌트 있음`만 뜨고 원문은 감춰진다.
`힌트 비용: 0`은 예산 밖에 두는 탈출구다 — **진행에 꼭 필요한 길잡이 힌트**는
여기에 넣어야 힌트 예산이 바닥나 게임이 멈추는 사고를 막을 수 있다.

**8. 특수 단서로 만들려면 `잠김이름`을 쓴다.**
`잠김이름`이 있는 단서만 **특수 단서 탭**에 모아 보여준다. 잠긴 동안에는 이 이름이
실명을 대신하고, 해제조건은 위치와 개수로만 표시된다
(`"의무실에서 확인할 것 2개"`) — 선행 단서의 실명은 절대 노출되지 않는다.
`정하람의 소지품` 같은 이름은 그대로 두면 범인을 흘리므로 반드시 덮어쓴다.
→ `잠김이름: ???` 또는 `잠김이름: ??? — 어느 인물의 소지품`

## 채점 문항

문항(범인 지목·살해 방법 등)은 단서와 캐릭터가 확정된 뒤에 따로 작성한다.
지금은 `src/data/<id>/quiz.ts`의 더미 문항이 그대로 남아 있다.

## 변환 후 확인

- `npm run check:content` — 원고와 코드가 어긋난 곳을 방향과 함께 보여준다.
  단서는 **누락·추가·순서**를 먼저 잡고, 그다음 필드를 하나씩 대조한다.
- `npm test` — 끊긴 해제조건, 순환 참조, 범인 수, 존재하지 않는 구역/인물 참조를
  **오류로** 잡아 실패시킨다.
- `npm run dev` → 심판 패널(`/#/s/<id>/gm`)의 **"시나리오 데이터 검사"** 섹션에서
  경고까지 확인. 밸런스 경고도 여기 뜬다.
- 심판 패널의 **단서 상태 관리** 목록에서 각 단서의 `비용 N회 · 선행 N개`를 보고
  의도한 게이팅이 그대로 들어갔는지 대조한다.
