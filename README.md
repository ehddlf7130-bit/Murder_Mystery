# 머더미스터리 진행 도구

동아리 박람회에서 운영하는 오프라인 머더미스터리 게임의 **진행 보조 웹툴**.
백엔드 없이 정적 사이트로 배포되며, 상태는 각 기기의 `localStorage`에만 저장된다.

## 두 종류의 기기

같은 URL로 접속해 갈래 화면에서 역할을 고른다.

| | 기기 | 화면 | 하는 일 |
|---|---|---|---|
| 📱 | 각자의 휴대폰 | `개인용` | 내 캐릭터의 배경·개인 목표 확인, 마지막에 채점 제출 |
| 💻 | **공용 노트북 1대** | `게임 진행용` | 맵 조사, 단서 열람, 남은 열람 횟수 관리 |
| 🎬 | 심판의 기기 | `/gm` | 리셋, 횟수 조정, 단서 강제 해제, 정답 키 |

> ⚠️ **진행 화면은 공용 노트북 1대에서만 연다.** 열람 횟수는 그 브라우저에만
> 저장되므로, 두 대에서 열면 횟수가 따로 세어진다. 심판 패널도 진행 상태를
> 공유해야 하므로 같은 노트북에서 열어야 한다.

## 개발

```bash
npm install
npm run dev        # http://localhost:5173 (--host라서 같은 와이파이의 휴대폰에서도 접속 가능)
npm test           # 게이팅·채점·시나리오 무결성 검사
npm run typecheck
npm run build      # dist/
```

## 게임 규칙 (코드가 강제하는 것)

- 게임 전체에 **총 열람 횟수**가 정해져 있다 (`Scenario.totalInvestigations`).
- 단서를 **처음** 열람할 때만 차감된다. 이미 본 단서는 언제든 무료로 다시 볼 수 있다.
- 차감이 발생하는 열람만 확인 다이얼로그를 거친다 — 여러 명이 한 노트북을
  돌려가며 조작하므로 오클릭 한 번이 예산을 태우는 것을 막는다.
- 턴 개념은 없다. 누구 차례인지 관리하지 않는다.
- **특수 단서**는 지정된 하위 단서를 **모두 열람 완료**하면 해제되고, 기본적으로
  **무료로** 열람된다. 상위 단서를 다시 선행조건으로 삼아 연쇄 게이팅을 만들 수 있다.
- 잠긴 단서는 이름 대신 `lockedLabel`로 표시하고, 해제 조건은 **위치와 개수만**
  알려 준다 (선행 단서의 실명을 노출하지 않는다).

규칙 계산은 전부 [src/lib/clueRules.ts](src/lib/clueRules.ts) 한 곳에 있다.
UI 컴포넌트는 직접 계산하지 않고 이 모듈을 경유한다.

## 새 시나리오 추가

UI 코드는 건드리지 않는다.

1. `src/data/<새-id>/` 폴더를 만들고 `characters.ts` / `areas.ts` / `clues.ts` /
   `quiz.ts` / `index.ts`를 작성한다 (`src/data/cruise/`를 복사해 시작).
2. [src/data/index.ts](src/data/index.ts)의 `registry` 배열에 한 줄 등록한다.
3. `npm test`로 데이터 무결성을 검사한다.

데이터 계약은 [src/types/scenario.ts](src/types/scenario.ts)에 정의되어 있다.

### 무결성 검사가 잡아 주는 것

[src/lib/validateScenario.ts](src/lib/validateScenario.ts)는 개발 모드에서 콘솔에
리포트하고, 심판 패널 하단에도 표시되며, `npm test`에서 오류가 있으면 실패한다.

- 존재하지 않는 선행 단서·구역·인물·선택지 ID
- 선행조건 순환 참조, 절대 열람할 수 없는 단서
- 진입 단서(선행조건 없는 단서)가 0개
- `isCulprit`이 정확히 1명이 아님, 범인 지목 문항의 정답 불일치
- 밸런스 경고: 총 열람 횟수로 유료 단서를 전부 열 수 있어 압박이 없음

**끊긴 선행조건은 현장에서 "단서가 영원히 열리지 않는다"로 터진다.** 이 검사가
그 사고를 배포 전에 막는 장치다.

## 현재 상태

시나리오 텍스트는 **더미 데이터**다 (`(더미)` 표기). 구조 검증용으로
캐릭터 4명 / 구역 4개 / 단서 12개(특수 4개) / 문항 4개를 채워 두었고,
확정된 내용으로 텍스트만 교체하면 된다.

`cruise` 시나리오의 `totalInvestigations`는 더미 기준(유료 단서 8개)으로 **6**으로
맞춰 두었다. 실제 텍스트를 채우면 단서 수가 늘어나므로 **리허설로 다시 조정해야 한다.**

## 배포 (GitHub Pages)

1. GitHub 저장소를 만들어 push한다.
2. 저장소 Settings → Pages → Source를 **GitHub Actions**로 설정한다.
3. `main`에 push하면 [.github/workflows/deploy.yml](.github/workflows/deploy.yml)이
   테스트 → 빌드 → 배포한다. 서브패스 배포를 위해 `VITE_BASE`를 저장소 이름으로
   자동 주입한다.

라우팅은 `HashRouter`를 쓴다 — GitHub Pages에는 SPA fallback이 없어 일반
라우터라면 새로고침 시 404가 난다.

### 박람회 당일 전에 반드시 할 것

앱은 PWA로 precache되므로 **한 번 접속한 기기는 와이파이가 끊겨도 동작한다.**
당일 전에 리허설로 확인해 둘 것:

1. 배포된 URL에 휴대폰으로 접속한다.
2. 기기의 와이파이/데이터를 끈다.
3. 새로고침 → 앱과 시나리오가 그대로 떠야 한다.

현장에서는 접속용 QR 코드를 미리 인쇄해 두면 편하다.
